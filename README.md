## 🚀 Featured Projects

<details>
<summary><b>⚡ WatchLog — Transformer-Based Log Anomaly Detection</b></summary>

<br/>

> An end-to-end log anomaly detection system that applies Transformer architectures to sequential log data, learning normalcy patterns and surfacing statistically anomalous events in real time — designed for production distributed infrastructure.

<div align="center">

| Attribute | Details |
|-----------|---------|
| **Stack** | Python · Transformers · Drain Algorithm · NumPy · Scikit-learn |
| **Datasets** | HDFS (~11M log entries, ~1.5 GB) · BGL Supercomputer Logs (~5M lines) |
| **Performance** | F1 Score ~0.89 · Precision ~0.91 · Recall ~0.88 on HDFS benchmark |
| **Architecture** | Transformer encoder for sequence modelling · reconstruction-error thresholding |
| **Pipeline** | Log parsing → Feature engineering → Model training → Evaluation |
| **Domain** | Distributed systems · Infrastructure reliability · AIOps |
| **Repository** | [github.com/solvingharshproblems/WatchLog](https://github.com/solvingharshproblems/WatchLog) |

</div>

**Why it matters:** Traditional rule-based alerting in distributed systems generates enormous false-positive noise. WatchLog learns what normal log sequences look like and flags genuine deviations — a meaningful step toward self-healing infrastructure. The Transformer architecture (replacing the earlier LSTM Autoencoder) captures long-range dependencies in log sequences that recurrent models miss.

<br/>
</details>

<details>
<summary><b>🔍 CodeForge — AI-Powered Code Review Assistant</b></summary>

<br/>

> An intelligent code review system that analyzes not just the diff, but the full impact boundary — identifying bugs at the interface between changed code and its callers/callees that diff-only tools routinely miss.

<div align="center">

| Attribute | Details |
|-----------|---------|
| **Stack** | Python · LLMs · Static Analysis · Call Graph Analysis |
| **Approach** | Multi-mode review: diff-only · full-codebase · targeted call-graph slicing |
| **Performance** | Targeted slicing achieves high bug-detection accuracy with minimal LLM token usage |
| **Key Insight** | Bugs frequently occur at the boundary between changed and unchanged code |
| **Domain** | Developer tooling · AI-assisted engineering · Static analysis |
| **Impact** | Catches cross-boundary bugs invisible to standard AI code review tools |

</div>

**Why it matters:** Most AI code review tools only see what changed. CodeForge reasons about the full impact surface — what callers expect, what callees provide, and where those contracts break after a change. This produces substantively higher bug catch rates without requiring a full-codebase context window.
